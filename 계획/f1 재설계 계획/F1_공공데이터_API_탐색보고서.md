## 3. F1 파이프라인 API 매핑

```
[Step A] 금지원료 체크
  ├─ f1_forbidden_ingredients DB (유지)
  └─ 수입식품 원료정보 API (사용가능여부=N 항목) 교차확인

[Step B] 원재료 허용여부 조회 + 성분코드 표시 + GMO 여부 확인
  ├─ Primary: 수입식품 원료정보 API (15111777)
  │     → INGD_NM / NKNM_NM / SCNNM_NM 으로 검색
  │     → EDIBLE_INFO + EDIBLE_Y/N + CHRTR_INFO_CONT 수신
  │     → verdict: EDIBLE_INFO="가능" & CHRTR_INFO_CONT=null → 허용
  │               EDIBLE_INFO="가능" & CHRTR_INFO_CONT≠null → 조건부
  │               EDIBLE_INFO="불가" → 금지
  ├─ 필수 병행: 수입식품 성분코드 API (15094202)
  │     → 매칭된 원재료의 CPNT_CD 조회 (KOR_NM 앞 공백 strip)
  │     → UI 원재료 목록에 성분코드 함께 표시 (요구사항)
  └─ 보조 병행: 식품 원재료 정보 조회 API (15111913)
        → ORM_STD_NM 으로 검색 후 GMO_YN 확인
        → GMO_YN="Y" 원재료 존재 시 F1 결과에 gmo_ingredients[] 포함
        → F3 product_keywords에 "GMO" 플래그 전달 (서류 매칭·경고 정확도 향상)

[Step C] 기준규격 수치 비교
  └─ Primary: 식품첨가물 기준규격 현황 API (15116583)
        → 품목한글명 + 식품유형으로 검색
        → 기준규격값 + 단위 수신 → 실측값과 비교

[Step D] 법령 인용
  └─ Pinecone RAG (유지, 표시 전용)
```

## 4. 제약사항 및 리스크

| 항목 | 내용 | 대응 방안 |
|------|------|---------|
| **트래픽 제한** | 개발계정 10,000건/월 | 운영 전 심의승인 신청 필수 |
| **실시간 지연** | 원재료 N건 × API 호출 → 응답 지연 가능 | 배치 조회 + 결과 캐싱 (Redis 또는 Supabase) |
| **단위 불일치** | mg/kg, g/L, ppm, % 혼재 | 단위 정규화 레이어 필수 (unit_converter.py 확장) |
| **이름 불일치** | API 한국어명 ↔ F0 원재료명 차이 | 퍼지 매칭 또는 동의어 테이블 보완 |
| **기준값 텍스트** | "불검출", "적정량" 등 비수치 기준값 | 수치 파싱 실패 시 HITL-1로 에스컬레이션 |
| **API 가용성** | 외부 API 장애 시 전체 파이프라인 중단 가능 | Circuit breaker + fallback(캐시/수동 입력) 구현 |
