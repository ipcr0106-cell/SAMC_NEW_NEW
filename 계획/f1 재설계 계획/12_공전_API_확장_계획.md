|--------|---------|-----------|
| 3388 | 건강기능식품공전 | https://www.safetydata.go.kr/disaster-data/view?dataSn=3388 |
| 3389 | 식품첨가물공전 | https://www.safetydata.go.kr/disaster-data/view?dataSn=3389 |
| 3390 | 식품용기구및용기.포장공전 | https://www.safetydata.go.kr/disaster-data/view?dataSn=3390 |

**제공기관:** 행정안전부 재난안전데이터과

## 3. 활용 시나리오

### 3-1. Step C 기준규격 보강 (F1)

현재 `03_Step_C_기준규격_설계`는 `15116583` (첨가물 기준규격 현황) 단독 사용. 공전 원문과 대조 가능:

```
15116583: 기준규격 수치 + 단위
  + 
3389 (첨가물공전): 해당 품목의 전체 사용기준·표시기준 조항 원문
  → 더 풍부한 컨텍스트로 HITL-1/2 판정 근거 제공
```

### 3-2. Step D 법령 인용 교체 (F1)

```
기존: Pinecone 유사도 검색 → 청크 5건
교체: 공전 API 조항 검색 → 원문 조항 5건
장점: 원문 최신, 조 번호 정확, 재임베딩 불필요
단점: 시맨틱 검색 품질은 Pinecone보다 낮을 수 있음 (키워드 기반 가정)
```

### 3-3. F3 기구·용기·포장 서류 강화

현재 F3는 `FoodCategory="기구또는용기.포장"` 조건을 다루지만, 관련 법령 본문 참조 미흡.
**3390 (식품용기구및용기.포장공전)**으로 해당 카테고리 서류 매칭 근거 강화.

### 3-4. F4 라벨 표시사항 검토 강화

F4는 현재 `food_code_text`, `additive_code_text` Pinecone 조회.
**3391 (식품공전)의 제5장 표시기준 조항을 API로 조회**하면 최신 표시 의무사항 확보.

### 3-5. F5 한글표시사항 시안

동일한 원문 API로 최신 표시 템플릿 유지 가능.

## 5. 제안 아키텍처: Pinecone + 공전 API 하이브리드

단순 대체보다 **Pinecone을 "공전 API에서 자동 갱신되는 캐시"로 재정의**:

```
[정기 동기화 (예: 주간)]
  공전 API (원문)
      ↓ 크롤·파싱
  청크 분할 + 임베딩
      ↓
  Pinecone 갱신

[실시간 조회]
  F1 Step D / F3 / F4 / F5
      ↓
  Pinecone 시맨틱 검색 (빠름)
      +
  공전 API 조항 번호로 원문 확인 (정확도 보강)
```

**장점:**
- 기존 Pinecone 시맨틱 검색 UX 유지
- 공전 API가 원문의 "신뢰 소스"로 기능 → 임베딩이 틀려도 복구 가능
- Pinecone 수작업 임베딩 부담 제거 (자동화)

## 6. Phase 계획 (재설계 본 배포 P7 완료 후 시작)

| Phase | 범위 | 완료 기준 |
|-------|------|----------|
| **Q0 조사** | safetydata.go.kr 4개 API 활용신청 + 샘플 응답 검증 | 필드 구조 확정, 응답 샘플 저장 |
| **Q1 설계** | 하이브리드 아키텍처 확정, 동기화 Job 설계 | 별도 설계 문서 (본 문서의 후속) |
| **Q2 동기화 파이프라인** | 공전 API → 청크 → Pinecone 자동 갱신 Job | 주간 동기화 자동 실행 |
| **Q3 Step D 전환** | F1 Step D에 공전 API 조항 번호 직접 노출 | 판정 근거 UI에 조 번호 정확 표기 |
| **Q4 F3/F4/F5 확장** | 기구·용기·포장 카테고리 강화, F4 표시기준 강화 | 관련 기능 골든셋 품질 향상 |
| **Q5 Pinecone 재검토** | 수작업 임베딩 제거, 하이브리드 단일화 | Pinecone 갱신 자동화율 100% |

## 8. 본 재설계(00~11) 범위 外 이유

- 본 재설계는 **F1 수입판정 로직 재구현**에 집중
- 공전 API는 **법령 원문 공급 레이어 혁신** — 별도 관심사
- 동시 진행 시 스코프 확대로 일정 지연 위험
- 본 재설계 후 운영 데이터로 공전 API ROI 재평가가 합리적
