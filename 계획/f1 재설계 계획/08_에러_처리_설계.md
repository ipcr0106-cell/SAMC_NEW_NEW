# 08. 에러 처리 설계

> 의존: [F1F2_재설계_명세.md §6-7](./F1F2_재설계_명세.md)
> 산출물: `backend/services/data_go_kr/exceptions.py`, 각 Step 서비스의 에러 흐름

---

## 1. 목적

F1 파이프라인에서 발생하는 에러를 3계층으로 구분하고, 각각의 대응 방식을 표준화한다.

---

## 2. 에러 3계층 매트릭스

| 계층 | 정의 | 노출 방식 | 담당자 액션 |
|------|------|----------|-------------|
| **① 차단성 에러** | 입력 누락·필수 선행 단계 미완료 | HTTP 400, `error_code` 필드 | 선행 단계 수정 후 재실행 |
| **② 복구 가능 에러** | 외부 API 일시 장애·Rate limit | HTTP 503 OR 재시도 후 경고 | 재시도 / 잠시 후 재실행 |
| **③ 조용한 품질 저하** | 매칭 실패·부분 데이터 누락 | 결과 내 `unidentified[]`·경고 배너 | HITL-1 검토 |

## 3. 에러 코드 정의

```python
# services/data_go_kr/exceptions.py

class F1PipelineError(Exception):
    """F1 최상위 에러 기반 클래스."""
    code: str
    transient: bool = False

# ① 차단성
class F0NotCompletedError(F1PipelineError): code = "F0_NOT_COMPLETED"
class F0NotApprovedError(F1PipelineError): code = "F0_NOT_APPROVED"   # HITL-0 도입 후
class NoIngredientsError(F1PipelineError): code = "NO_INGREDIENTS"
class FoodTypeMissingError(F1PipelineError): code = "FOOD_TYPE_MISSING"

# ② 복구 가능
class DataGoKrApiError(F1PipelineError):
    code = "DATA_GO_KR_API_ERROR"
    transient: bool = True   # 기본 True

class RateLimitExceededError(DataGoKrApiError):
    code = "DATA_GO_KR_RATE_LIMIT"
    transient: bool = False  # 일일 한도는 즉시 복구 불가

class ConfigError(F1PipelineError):
    code = "CONFIG_ERROR"
    transient: bool = False  # 엔드포인트 URL 오류 등

# ③ 품질 저하 — Exception 이 아닌 결과 객체의 필드로 표현
#   Feature1Output.escalations[] 에 아래 사유로 누적
#   - "ingredient_unidentified"
#   - "spec_value_non_numeric"
#   - "unit_normalization_failed"
#   - "conflicting_api_results"
```

## 5. Circuit Breaker (data.go.kr API)

5분 window 내 연속 실패 횟수로 차단 모드 전환:

| 상태 | 조건 | 동작 |
|------|------|------|
| CLOSED (정상) | 실패율 < 50% | 정상 호출 |
| OPEN (차단) | 5분 내 20회 연속 실패 OR 실패율 > 80% | 캐시만 사용, API 호출 차단, 미스 시 `unidentified` |
| HALF_OPEN (복구 시도) | OPEN 30분 경과 | 1건 테스트 호출 → 성공 시 CLOSED, 실패 시 OPEN 유지 |

구현: `services/data_go_kr/circuit_breaker.py` (in-memory, 프로세스 단위)

## 6. Fallback 전략 (API 장애 시)

| 시나리오 | Fallback |
|---------|---------|
| 15111777 장애 | `f1_forbidden_ingredients` (금지만 확인) + 전체 `unidentified` → HITL-1 |
| 15094202 장애 | 성분코드 빈 값으로 결과 반환 (UI 미표시) |
| 15116583 장애 | Step C 전체 skip → `standards_check=[]` + 경고 |
| 15111913 장애 | GMO 플래그 누락 → F3에서 keyword hint만 사용 (현 동작) |

> **원칙:** API 장애가 전체 파이프라인 중단을 의미하지 않도록 부분 실패 허용. 다만 담당자에게 **명시적 경고**.

## 7. 의미적 오류 (§7 구조적 리스크) 완화

| 리스크 | 완화 장치 |
|--------|---------|
| R1 doc_type 오입력 | Upload 시 최소 키워드 검증 (원재료배합비율표 → "%", "배합" 중 1 이상 필수) → 부재 시 경고 배너 |
| R2 제품 불일치 | `basic_info.product_name` ↔ `cases.product_name` Levenshtein 거리 측정 → 임계치 초과 시 배너 |
| R3~R6 | **HITL-0 단계 승인 강제화**가 유일한 완화책 (`05_HITL_플로우_설계` 참조) |
