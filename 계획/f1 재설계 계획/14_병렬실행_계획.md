- **호출 방식** — 부모 세션이 한 어시스턴트 메시지 안에 `Agent()` 도구 4개(W1-A/B/C/D)를 동시 호출. 서브에이전트는 독립 컨텍스트로 실행되며 결과는 부모 세션이 수신·병합.
- **서브에이전트 타입** — `subagent_type="executor"`, 모델은 W1-A만 `opus`(외부 API 안정성), 나머지 3개는 `sonnet`.
- **동기화 불필요** — 동일 git 작업트리를 공유하므로 세션 간 pull/push 프로토콜 없음. 단, 서브에이전트는 자기 경계 파일만 편집하므로 충돌 자연 회피.
- **검증 lane 분리** — 4 트랙 완료 후 별도 `Agent()` 호출로 `code-reviewer`(opus) → `verifier` 순차 실행. 부모 세션은 작성 결과를 **직접 승인하지 않는다**(OMC 자기승인 금지).

#### 8-2-2. Day 0 인터페이스 픽스 (부모 세션 담당)

Agent() 병렬 호출 **직전에** 부모 세션이 아래 3개 인터페이스 스켈레톤을 먼저 커밋하여 4 트랙이 공유 참조할 수 있도록 동결한다.

| 파일 | 담당 트랙 | Day 0 스켈레톤 범위 |
|------|----------|---------------------|
| `backend/exceptions.py` | W1-C 확장 | `DataGoKrError` 계열 5개 클래스 시그니처·속성 동결 |
| `backend/models/f1_types.py` (신규) | W1-B 확장 | `Feature1Output` 핵심 필드 + `DataGoKrEndpoint` Enum |
| `backend/services/data_go_kr/client.py` (신규) | W1-A 본체 | `DataGoKrClient` 클래스 4개 메서드 시그니처 선언 |

**커밋 메시지:** `feat(f1): Wave 1 Day 0 interface skeleton`

#### 8-2-3. 트랙 간 파일 경계 (subagent 프롬프트에 명시)

각 Agent() 프롬프트에 아래 표의 "편집 허용/금지 경로"를 **반드시 포함**한다. 서브에이전트는 본인 경계 외 파일을 건드리지 않는다.

| 트랙 | 편집 허용 | 편집 금지 |
|------|----------|----------|
| W1-A | `backend/services/data_go_kr/**`, `backend/db/migrations/016_*.sql`, 관련 단위테스트 | B/C/D 영역, `feature1.py`, `계획/**/*.md` |
| W1-B | `backend/models/f1_*.py`, `backend/models/judgment.py`(F1 필드만), `frontend/types/pipeline.ts` F1 영역 | 타 트랙 영역, `feature1.py`, `계획/**/*.md`, judgment.py의 F2/F3/F4/F5 필드 |
| W1-C | `backend/exceptions.py`(Day 0 스켈레톤 확장), `backend/middleware/error_handler.py`, `backend/services/data_go_kr/circuit_breaker.py` | 타 트랙 영역, `feature1.py`, `계획/**/*.md` |
| W1-D | `backend/utils/unit_converter.py`, `backend/constants/density.py`, 관련 단위테스트 | 타 트랙 영역, `feature1.py`, `계획/**/*.md` |
| 부모 세션 | `계획/**/*.md`, Day 0 3개 스켈레톤 파일, `.env.example`, PR 본문 | 트랙 결과물은 서브에이전트에게 위임 |

#### 8-2-4. 검증 루프 (자기승인 금지)

```
[작성 lane]
  Agent(W1-A) ──┐
  Agent(W1-B) ──┤  (단일 메시지 병렬 호출)
  Agent(W1-C) ──┤
  Agent(W1-D) ──┘
        ↓ 4 트랙 완료
[리뷰 lane]
  Agent(code-reviewer, opus) → 결과 수신
        ↓ 이슈 있으면 해당 트랙 Agent() 재호출
  Agent(verifier) → 게이트 체크 증빙
        ↓ 통과
[PR 생성]
```

- **부모 세션은 자기 자신의 작성 작업을 직접 승인하지 않는다** — 반드시 별도 `code-reviewer`/`verifier` Agent() 호출 결과로 승인 근거 확보.
- 리뷰에서 지적된 사항은 **해당 트랙 Agent()만 재호출** (나머지 트랙 건드리지 않음).

#### 8-2-5. 실패 시 단일 트랙 롤백

| 상황 | 대응 |
|------|------|
| 특정 트랙 Agent() 실패·게이트 미달 | `git restore backend/<해당트랙경로>` 후 해당 Agent()만 재호출. 나머지 트랙 결과 유지 |
| 경계 침범 파일 편집 감지 | 부모 세션이 `git diff --name-only HEAD~` 확인 → 경계 외 파일은 `git restore` |
| `code-reviewer` 차단 이슈 | 해당 트랙만 수정 재호출, 다른 트랙은 그대로 PR 포함 |
| 부모 세션 context 초과 | 14번 문서 + Day 0 스켈레톤 3파일만 재로드로 복구 가능 |
