## 1. 목적

## 2. 테스트 계층

```
단위 테스트 (unit)      — 함수 단위, mock 기반
통합 테스트 (integration) — 서비스 계층, Supabase/Pinecone 실연결
E2E 테스트 (e2e)         — HTTP 라우터 → 프론트 시나리오 스모크
골든셋 (regression)      — 과거 실제 케이스 N건 재생
```

## 6. 골든셋 (회귀 테스트)

### 6-1. 구성

과거 실제 운영 케이스 50~100건 선별:

```
backend/tests/goldenset_f1_v3/
├── cases/
│   ├── case_001_korean_rice_cake/
│   │   ├── input_f0.json        # F0 파싱 결과 (고정)
│   │   ├── expected_verdict.json # 담당자 최종 판정 (정답)
│   │   └── expected_standards.json
│   └── ...
└── run_goldenset.py
```

### 6-2. 목표 지표

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| **verdict 일치율** | ≥ 80% | AI 추천 verdict vs 실제 담당자 최종 판정 |
| **금지원료 감지율** | 100% (Recall) | 실제 금지원료 hit 누락 없음 |
| **오탐률** | ≤ 5% | 허용 원료를 금지로 오분류 |
| **기준규격 정확도** | ≥ 90% | pass/fail 실측 비교 |
| **HITL-1 전환율** | ≤ 30% | "unidentified + restricted 있음" 케이스 비율 |

### 6-3. 실행 정책

- 매 PR에서 자동 실행 (5건 mini 서브셋)
- 매 배포 전 전체 골든셋 실행
- 결과는 `goldenset_run_v3_{date}.json`으로 저장·누적

## 9. CI 구성

```yaml
# .github/workflows/f1_tests.yml
- name: Unit tests
  run: pytest backend/tests/f1_rewrite/unit -v --cov

- name: Integration (gated on unit pass)
  run: pytest backend/tests/f1_rewrite/integration -v
  env:
    SUPABASE_URL: ${{ secrets.TEST_SUPABASE_URL }}
    F1_DATA_GO_KR_API_KEY: ${{ secrets.F1_DATA_GO_KR_TEST_KEY }}

- name: Goldenset mini (매 PR)
  run: python backend/scripts/f1_run_goldenset.py --subset mini

- name: Goldenset full (매 release)
  if: github.event_name == 'release'
  run: python backend/scripts/f1_run_goldenset.py --subset full
```

## 10. 테스트 작성 규약

- `pytest` 기반
- async는 `pytest-asyncio`
- fixture: `conftest.py`에서 API 키·Supabase 클라이언트 주입
- 각 테스트는 독립 (상태 공유 금지)
- Assertion 메시지에 비교값 명시
