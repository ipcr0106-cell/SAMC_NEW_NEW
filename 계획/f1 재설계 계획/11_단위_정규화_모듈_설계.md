## 1. 목적

## 3. 변환 규칙

정규화 기준 단위는 **`mg/kg`** (고체·분말 기본).

| 원본 단위 | 변환식 | 비고 |
|----------|--------|------|
| `mg/kg` | 그대로 | 기준 |
| `ppm` | 그대로 (mg/kg ≡ ppm 고체 기준) | |
| `g/kg` | × 1,000 | |
| `μg/kg` | × 0.001 | |
| `%` | × 10,000 | 1% = 10,000 mg/kg |
| `g/L` | × (1000 / density) | 액체 → 고체 단위 (비중 필요) |
| `mg/L` | × (1 / density) | 동일 |
| `IU/kg` | ❌ 변환 불가 | `UnitIncompatibleError` |
| `null` / `""` | → `"적합"` 등 비수치로 간주 | `parse_non_numeric_spec` 호출 |

---

## 4. 비수치 기준값 처리

```python
@dataclass
class SpecEvaluation:
    kind: Literal["numeric", "non_detect", "qualitative", "unknown"]
    value: Optional[float] = None
    label: Optional[str] = None    # "적합" / "불검출" 원문
    requires_hitl: bool = False
```

**매핑:**

| SPEC_VAL 텍스트 | kind | requires_hitl |
|----------------|------|---------------|
| "85.0이상" | numeric (비교 가능) | False |
| "불검출" | non_detect | False (실측값 > 0 이면 fail) |
| "음성" | non_detect | False |
| "적합" | qualitative | **True** (담당자 판단) |
| "적정량" | qualitative | **True** |
| 파싱 불가 | unknown | **True** |

---

## 5. 수치 파싱

`SPEC_VAL`에는 `"85.0이상"`, `"0.1이하"`, `"0.01~0.1"` 등 범위 표현도 있음.

```python
def parse_numeric_spec(spec: str) -> tuple[Optional[float], Optional[float]]:
    """
    반환: (min_val, max_val). 단방향이면 한쪽만 값.

    예시:
        "85.0이상"  → (85.0, None)
        "0.1이하"  → (None, 0.1)
        "0.01~0.1" → (0.01, 0.1)
        "5.0"       → (5.0, 5.0)
    """
```

**API 원본 필드 우선순위:**
1. `MIMM_VAL` / `MXMM_VAL` (이미 수치로 파싱돼 있음) → 최우선
2. 둘 다 null이면 `SPEC_VAL` 텍스트 파싱
3. 그것도 실패 → `parse_non_numeric_spec` 호출

## 7. 에지 케이스

| 케이스 | 처리 |
|--------|------|
| 단위 없이 순수 숫자만 존재 (`UNIT_NM=null`) | `SPEC_VAL_SUMUP` 문구에서 단위 추정 → 실패 시 HITL |
| 복합 단위 (`"mg/kg (건조물 기준)"`) | 접미 주석 무시, `mg/kg` 추출 |
| 한글 단위 (`"퍼센트"`) | 매핑 테이블로 정규화 |
| 동일 품목 내 상충 단위 | `T_KOR_NM` 별로 독립 처리 |

---

## 8. 테스트 포인트

- [ ] `normalize_to_common_unit(5, "%")` → `(50000, "mg/kg")`
- [ ] `normalize_to_common_unit(100, "g/L", density=1.0)` → `(100000, "mg/kg")`
- [ ] `parse_numeric_spec("85.0이상")` → `(85.0, None)`
- [ ] `parse_numeric_spec("0.01~0.1")` → `(0.01, 0.1)`
- [ ] `parse_non_numeric_spec("불검출")` → `SpecEvaluation(kind="non_detect")`
- [ ] `normalize_to_common_unit(1, "IU/kg")` → `UnitIncompatibleError`

---

## 9. 남은 결정사항

- 🟡 `DENSITY_BY_FOOD_TYPE` 테이블 구축 방법 (수작업 vs 공공 참조)
- 🟡 "적합" 같은 qualitative 기준을 매번 HITL 에스컬레이션할지 (케이스량 폭증 우려) vs 기본값을 통과로 처리할지
- 🟡 범위 표현 파서(`0.01~0.1`) 의 정규식 보편성 — 포털 문서 구조를 보고 확정
