## BUG-1 심각도 하향: 높음 → 중간

### 원래 주장
> "마리화나 추출물" 같은 케이스가 게이트를 통과함 — 심각도 높음

### 재평가
- Step 0 탈출 후에도 **Step 1의 5단계 매칭 체인**이 2차 방어선
- trgm 퍼지 매칭에서 "마리화나 추출물" → "대마초" 계열 잡힐 가능성 높음
- `f1_forbidden_ingredients`는 ~200행 소규모 게이트, `f1_allowed_ingredients`의 prohibited 매칭이 실질 그물
- **진짜 위험**: Step 1에서도 안 잡히는 극히 드문 케이스

### 수정 판정
- 심각도: **중간** (defense-in-depth 보강)
- 수정은 권장하지만 긴급하지는 않음
- 수정 범위: normalize + 양방향 substring 추가 (~10줄)

## 과잉/YAGNI 판정

| 교훈 | 판정 | 이유 |
|---|---|---|
| **Loader/Adapter 패턴** | 과잉 | Python `monkeypatch`로 동일 효과. 프로덕션 코드에 추상화 불필요 |
| **Rule-based Evaluator** | YAGNI | 룰 1개에 인터페이스는 과도. 룰 3개 이상일 때 재검토 |
| **에스컬레이션 별도 모듈** | 과잉 | `thresholds_config.py`에 이미 부분 분리. 현재 규모에서 충분 |
| **withRetry** | 과잉 | Supabase 연결 장애 빈도 낮음. 실제 장애 발생 전까지 불필요 |
| **NFC 정규화** | 과잉 | F0이 파싱한 결과를 받으므로 자모 분리 확률 극히 낮음 |
| **normalizeForComparison 전각괄호/중점** | 과잉 | BUG-1 수정에 필요한 건 공백제거+lowercase뿐 |
| **부위 사전** | 과잉 | 현재 `validate_part_restriction()` 충분. 사전 관리 비용 > 이득 |

## 요구사항 미확인 항목

03번 파일의 "갭"으로 분류했지만, **F1 요구사항에 있는지 확인 안 됨:**

| 항목 | 문제 |
|---|---|
| GMO 대상 식별 | 기획서에 F1 범위인지 확인 필요 |
| 알레르겐 교차검사 | 기획서에 F1 범위인지 확인 필요 |
| 필수서류 자동 취합 | 기획서에 F1 범위인지 확인 필요 |
| 특수 에스컬레이션 트리거 | health_functional_suspect 등이 F1 요구사항에 있는지 미확인 |

**newsamc에 있다고 F1에도 필요한 것은 아님.** "갭"이 아니라 "확인 필요 항목"으로 격하.
